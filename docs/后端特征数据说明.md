# BP LAB 后端特征数据说明

> 给后端分析/BP 权重更新使用。数据由 `scripts/fetch_opgg_mcp.py` 和 `scripts/build_backend_features.py` 生成。

## 1. 输出文件

| 文件 | 内容 |
|---|---|
| `data/bp_backend_features.json` | 全量嵌套特征，推荐后端直接读取 |
| `data/champion_role_features.csv` | 英雄 × 分路一行，含时长曲线、OP.GG MCP 摘要、trait 标签 |
| `data/pair_features.csv` | 双人协同组合（有向，方便 join） |
| `data/counter_features.csv` | 英雄/分路 × 对手的 counter 记录 |
| `data/opgg_mcp.json` | MCP 原始结构化数据（已解析） |
| `data/champions.json` | 原有英雄时长曲线/位置/图标数据 |

## 2. `bp_backend_features.json` 结构

```text
meta
  championCurves: 原 OP.GG 网页快照的版本、区域、抓取时间、时长桶
  mcp: OP.GG MCP 的 tier、区域说明、抓取时间、失败列表
  builtAt / champions / roleEntries / pairIndexEntries / counterChampionRoles

champions[key]
  key / ddragonId / name / title / tags / positions / icon
  traits: {frontline, backline, engage, peel, poke, splitpush, dive, waveclear}
  info: {attack, defense, magic, difficulty}
  roles[role]
    curve: 原 OP.GG 时长曲线 5 桶（rate/average/rank）
    summary: {play, winRate, pickRate, banRate, kda, tier, rank}
    damageType: AP / AD / BOTH / UNKNOWN
    counters: [{name, key, play, myWinRate, counterWinRate, direction}]
    synergies: [{championId, name, key, position, play, win, winRate, score, scoreRank}]
    trends: [{version, winRate, rank}]

pairs
  `"{champion}:{role}|{partner}:{partnerRole}"` -> {winRate, play, win, score, scoreRank, source}

counters
  `champions[champion][role][opponent]` -> {play, myWinRate, counterWinRate, direction}
```

注意：`synergies` 是列表，`position` 表示搭档位置（top/jungle/adc/support）；不是按角色分组的对象。

## 3. CSV 字段

### champion_role_features.csv

`champion_key, ddragon_id, champion_name, title, role, damage_type, play, win_rate, pick_rate, ban_rate, kda, tier, rank, curve_lt25, curve_25_30, curve_30_35, curve_35_40, curve_40plus, frontline, backline, engage, peel, poke, splitpush, dive, waveclear`

- `win_rate` / `pick_rate` / `ban_rate` 为 OP.GG MCP 的百分数（0–100）
- `curve_*` 为原 OP.GG 网页快照的胜率（0–100），不是 MCP
- `tier` 为 OP.GG 梯队（1=OP, 2=Strong, 3=Good, 4=Average, 5=Weak）

### pair_features.csv

`champion, role, partner, partner_role, play, win, win_rate, score, score_rank, source`

- 有向记录；同一组合会出现两个方向。去重可按 `champion < partner`。
- `win_rate` 是原始双人组合胜率（0–100），不是扣主效应后的 residual。

### counter_features.csv

`champion, role, opponent, play, my_win_rate, counter_win_rate, direction, source`

- `direction = strong` 表示 `my_win_rate >= 50`，`weak` 表示 `< 50`
- 只覆盖 OP.GG MCP 返回的 strong/weak counter 样本，不代表所有对位

## 4. 更新流程

```bash
python3 scripts/fetch_opgg_mcp.py       # 拉 MCP 英雄/分路统计、counter、synergy、trends
python3 scripts/build_backend_features.py
python3 scripts/export_backend_csv.py
```

当前 MCP 数据已抓到 **171 个英雄 / 254 个英雄-分路条目 / 0 失败**（2026-11-11 20:41）。

## 5. 使用限制

- **MCP 没有 `region` 参数**：不能保证是韩服 KR；当前 meta 写的是 `region: not specified by MCP`。如果后端要韩服专属权重，必须用 Riot Match-V5 或自行抓取/授权数据。
- **MCP 没有游戏时长桶**：`curve` 仍来自原有 OP.GG 网页快照，不是 MCP。
- **MCP 的 `winRate` 是原始表现**，不是因果强度；不能直接作为训练标签。
- **pair `winRate` 是原始双人组合胜率**，不是扣掉两个英雄主效应后的 `γ`；后端若要训练，请用比赛级数据重新估计 residual。
- 生产使用前确认 OP.GG MCP 的 rate limit/SLA/商业授权；长期数据源优先 Riot Match-V5。
